# 運用手順

このページはメンテナー向けの実務手順です。参加者向けの状態と判断基準は[運用フロー](workflow.md)を参照してください。現時点の運営者はリポジトリ所有者です。協力者にCloudflareの管理権限を渡さなくても、公開IssueとPRで参加できます。

## 定期確認

週に1回を目安に、匿名投稿、未整理のIssue、PR、公開サイトの状態を確認します。ボランティア運営のため回答期限を保証するものではありません。対応が滞る場合は、その旨をREADMEか公開Issueに記します。

1. Cloudflare D1のConsoleで `SELECT id, municipality, category, title, detail, created_at FROM proposals WHERE status = 'pending' ORDER BY created_at ASC LIMIT 50;` を実行する。結果をローカルファイルや公開コメントへ一括コピーしない。
2. 既存Issueと重複していないか、個人情報や第三者を特定できる記述、誹謗中傷、緊急相談、公式申請と誤解される内容がないか確認する。
3. 公開に適する提案は、地域、課題、提案の要点、未確認点だけを自分の言葉でIssueへ整理する。投稿原文やD1の識別番号は載せない。元の投稿に個人情報があればIssue本文に残さない。
4. Issueを[公開ボード](https://github.com/users/kechirojp/projects/2/views/1)の「提案」に入れる。確認した論点と次の作業を記す。重複なら既存Issueに要点を追記し、元投稿だけを公開しない。
5. 転記後の元投稿は、対象IDを照合してD1から削除し、`SELECT COUNT(*)` で残件0を確認する。公開できない投稿も受信から90日以内に削除する。削除前に対応するIssueのURLを控える必要があれば、公開Issue側に関連情報を記録する。

公開に適さない投稿の原文は引用しません。削除の判断は理由を個人情報なしの運用記録に残せます。連絡先を取得しないため投稿者への個別返信はできません。

## Issueとボード

新しいIssueは重複、対象地域、調べる問い、出典の有無を確認します。事実確認、提案、推計を混同している場合は区別できるよう追記を依頼します。状態を変えるときは、担当者、根拠、未確認点、次の作業をコメントします。見送りや終了も理由を残します。実証については、実施主体による正式な決定を確認するまで「実証中」に移しません。

## PRの確認と公開

1. PRの目的と関連Issueを確認する。出典、確認日、未確認点、個人情報の有無、事実と提案の区別を見る。
2. コード変更では `npm run check` とGitHub Actionsの結果を見る。投稿受付、認証、D1、個人情報の扱いを変える場合は変更者以外のレビューと本番相当の確認を待つ。
3. 採用・修正依頼・見送りをPRに記録する。統合後はCloudflare Pagesのデプロイ成功と、該当ページの公開表示を確認する。フォーム関連の変更では正常投稿と拒否動作も確認し、確認用投稿の原文を削除する。
4. 公開に問題が出たらCloudflare Pagesで直前の正常なデプロイへ戻し、影響、暫定対応、再発防止をIssueに記録する。

## 権限と秘密情報

CloudflareのD1、環境変数、Turnstile秘密キーへの権限は運用に必要な人だけに与えます。秘密キー、投稿原文、個人情報をIssue、PR、コミット、スクリーンショットに含めません。権限を追加・削除したときは運営者が確認します。秘密情報の流出が疑われる場合は公開を止めてキーを更新し、影響を調べます。

## サイトと投稿受付

サイトは `npm run build` で `dist/` に生成する。Cloudflare Pagesのビルドコマンドは `npm run build`、出力ディレクトリは `dist`。Pages Functionsの `functions/api/proposals.js` が `POST /api/proposals` を受ける。

D1データベースを作り、`migrations/0001_proposals.sql` を適用する。Pages Functionsへ `DB` の名前でバインドする。Turnstileウィジェットを作成し、公開サイトキーをPagesの環境変数 `TURNSTILE_SITE_KEY`、秘密キーを暗号化された環境変数 `TURNSTILE_SECRET` に設定する。サイトキーはビルド時にも `TURNSTILE_SITE_KEY` として渡す。秘密キーはGitに入れない。

フォームは匿名で、名前・メール・住所を求めない。本文に個人情報を書かないよう表示する。受付データはD1内で非公開にし、運営者がCloudflareの管理画面から確認する。個人情報を除いてGitHub Issueに転記し、転記後または受信90日後に元データを削除する。D1の管理画面へのアクセス権は運営者だけに与える。一般公開の読み取りAPIは設けない。

Turnstileトークンはサーバー側で検証する。検証サービスやDBが使えないときは投稿を受け付けず、画面に再試行を案内する。受付成功時は識別番号だけを返し、本文を応答やログに出さない。

## リポジトリ

公開前に `npm run check` を実行し、リンク、フォーム、ビルドを確認する。GitHubの公開リポジトリではIssueとPRを有効にし、GitHub Projectsに「提案」「事実確認」「実証準備」「実証中」「結果公開」の状態を作る。市民投稿を公開Issueにする際は、元の投稿を丸写しせず要点・地域・検証事項だけを記す。
