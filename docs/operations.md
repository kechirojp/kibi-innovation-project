# 運用手順

## サイトと投稿受付

サイトは `npm run build` で `dist/` に生成する。Cloudflare Pagesのビルドコマンドは `npm run build`、出力ディレクトリは `dist`。Pages Functionsの `functions/api/proposals.js` が `POST /api/proposals` を受ける。

D1データベースを作り、`migrations/0001_proposals.sql` を適用する。Pages Functionsへ `DB` の名前でバインドする。Turnstileウィジェットを作成し、公開サイトキーをPagesの環境変数 `TURNSTILE_SITE_KEY`、秘密キーを暗号化された環境変数 `TURNSTILE_SECRET` に設定する。サイトキーはビルド時にも `TURNSTILE_SITE_KEY` として渡す。秘密キーはGitに入れない。

フォームは匿名で、名前・メール・住所を求めない。本文に個人情報を書かないよう表示する。受付データはD1内で非公開にし、運営者がCloudflareの管理画面から確認する。個人情報を除いてGitHub Issueに転記し、転記後または受信90日後に元データを削除する。D1の管理画面へのアクセス権は運営者だけに与える。一般公開の読み取りAPIは設けない。

Turnstileトークンはサーバー側で検証する。検証サービスやDBが使えないときは投稿を受け付けず、画面に再試行を案内する。受付成功時は識別番号だけを返し、本文を応答やログに出さない。

## リポジトリ

公開前に `npm run check` を実行し、リンク、フォーム、ビルドを確認する。GitHubの公開リポジトリではIssueとPRを有効にし、GitHub Projectsに「提案」「事実確認」「実証準備」「実証中」「結果公開」の状態を作る。市民投稿を公開Issueにする際は、元の投稿を丸写しせず要点・地域・検証事項だけを記す。
